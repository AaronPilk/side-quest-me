# Sidequest App Privacy inventory — October 2, 2026

This inventory describes current source, including the public-content moderation changes prepared for the next release. It is not proof that a hosted migration, release, or provider retention setting has been applied. No App Store Connect privacy answers were changed by this audit.

Apple's definitions and framework-specific guidance: [App Privacy Details](https://developer.apple.com/app-store/app-privacy-details/). Account-backed optional features still need disclosure. Apple treats data kept beyond real-time request servicing as collected; its guidance distinguishes Apple's own framework collection from the developer's collection. Generic free text does not require declaring every sensitive fact a user could type.

## Exact location and media metadata

`src/lib/location.ts` obtains a single foreground position after a user action, with low-accuracy preference. There is no background location watch or GPS history storage. Native Apple Maps search can receive that coordinate. Nearby event requests receive it transiently at the Worker, convert it to a five-character geohash and pass only the approximate search area to Ticketmaster. Exact GPS is not sent to OpenAI generation.

`shared/domain.ts`'s strict outing schema has area and Apple place ID, with no latitude/longitude fields. Private proposal storage strips coordinates in both Worker and SQL (`20261001214915_private_experience_discovery.sql`, including idempotency responses). Saved destination names/addresses remain. Profile photos and overlays strip metadata. Raw uploaded source video is copied without rewriting bytes and can preserve user-supplied location metadata; `probeMedia()` returns only curated technical properties. Final rendered clips/reels strip metadata with `-map_metadata -1`. Do not state that every uploaded original is GPS-free.

## What leaves the device

- Supabase/Cloudflare: account/session requests, saved preferences/summary, outing plans, generated quest/proposal records, social/licensing/reward state and chosen uploaded media. Client-only drafts are scoped to account/device and are not a cloud backup until uploaded.
- Apple Maps: the user-selected query/area or current coordinate for foreground place search; Apple handles its own framework data practices.
- Ticketmaster, if configured: town or approximate geohash, radius and date window; no account UUID, email or exact GPS.
- OpenAI quest generation, after named-provider consent: confirmed structured preferences, outing limits and relevant proposed places/quest context. It excludes raw imported summary, identity and exact device coordinates. Discovery's public listing names/categories/address may describe a venue, not a verified current device position. Responses use `store:false`; this does not establish zero provider retention.
- OpenAI public content screening, after separate explicit permission: submitted public profile name/username/bio or normalized photo; public Series title/premise/published chapter text and canonical quest instructions, including any public destination prose. Private drafts, unpublished future chapters and journal media are excluded. Outages/rejections prevent the new content from being saved/shared; existing private material and approved content are not bulk-screened.
- User-controlled external links: ChatGPT prompt copy, external event purchase pages and system share/save sheets. Sidequest does not obtain the user's ChatGPT history/subscription or collect external payment-card details.

## Retention facts

Local capture drafts expire after seven days and sign-out clears them. Source media becomes eligible for server cleanup after 30 days, but incomplete work, unresolved review, failed rendering or missing safe output can prevent cleanup. Ready final reels have no automatic expiry and are limited by the saved-reel allowance. Replaced profile photos are queued for cleanup; orphan photo cleanup uses a one-day grace period. Account deletion removes public availability, revokes shares, redacts private/user prose, queues R2 cleanup and removes Supabase authentication asynchronously. Minimal reward/accounting/licensing records persist to preserve established transactions; identifiers can remain linked to a tombstoned account.

Cloudflare observability is enabled at a 10% sampling rate. Log retention duration is **not specified in the repository**; verify the actual account product/retention settings before promising a duration. Supabase Auth/provider security log retention and OpenAI provider retention likewise cannot be inferred as zero from client code.

## Not collected as dedicated data types in current source

No requested phone number, home/mailing address, credit score, bank/card details, HealthKit/clinical record/fitness API data, disability/medical questionnaire, biometric template, address-book import, IDFA/device identifier, cross-app ad-attribution SDK, browsing history logger, saved search-history table, environment mesh or hand/head tracking exists. Structured exclusions ask whether to avoid an activity; they do not ask for a diagnosis or disability. Generic notes/summary/video can contain sensitive content a user voluntarily supplies, but Apple maps general text/audio to their content categories instead of every possible sensitive fact. No client crash SDK exists; Apple/TestFlight's own crash collection is not an app-integrated crash collector. Revise these answers if new SDKs, tracking, age verification, analytics or marketing data uses are added.
